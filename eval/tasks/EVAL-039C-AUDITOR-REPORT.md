Timeout / poll exhaustion / poll failure / download failure each yield one submit, one settlement, no resubmit (suite `FailureModesTest`; my probes agree).

## 3. Safe to make the first paid call under a signed spend record?

**Yes, with conditions.** Money-wise the harness is safe as built: every send is preceded by a reservation, no code path retries, the price check precedes the reservation, and the caps are enforced in USD-equivalent across cash, credits and INR. Before the first call: (1) AF-1 — reconcile the ceiling (175 in code vs 200 proposed) and the field names, and materialise `authorization.local.yaml` from the signed record by one reviewed step, with the roster sha bound (`Pricing(expected_roster_sha256=…)`); (2) AF-2 — `BatteryRun.open` must re-validate against the authorisation file; (3) AF-3 — wrap `_lifecycle` so every send persists an attempt. AF-4 must land before any Stage A Registry write; AF-5..AF-10 before Stage A reporting is trusted.
