## The idea in one paragraph

Some video faults do not exist in any single frame. A caption that is correct at the start of a
clip and wrong at the end. A person whose face becomes a slightly different person halfway
through. A shot that mirrors, so someone walking left-to-right suddenly walks right-to-left with
no cut to explain it. Look at any one frame and it is a perfectly good frame. The fault lives in
the *relationship between* frames.

To find out whether a checker can catch those faults, you normally need footage that already has
them, and a person to say where. This package does the opposite: it takes clean footage and
**breaks it on purpose, at a known moment, in a known way**. Because we performed the break, the
answer is already known exactly. Nothing needs annotating, and nothing needs to be generated by a
paid model. That is the same trick that made the project's Devanagari text battery cheap.

## What is in here

| File | What it does |
|---|---|
| `clipseq.py` | The clip container. Stores a clip as ordered lossless frames plus a frame rate, and hashes it so "the same clip" is a checkable fact. Fails closed on anything it cannot read with certainty. |
| `perturbations.py` | The thirteen deterministic ways to break a clip. Each returns the broken clip **and** the exact truth record: which transformation, which parameters, which frames, which region. |
| `build_dummy_clips.py` | Twelve constructed stand-in clips, so the machinery can be proven today. **They qualify nothing** — see the warning below. |
| `ingest_clips.py` | Turns real supplied video files into clips, using local ffmpeg. No account, no upload, no spend. |
| `build_perturbation_pack.py` | Builds and verifies the whole pack: fixtures, clean controls, deliberately-corrupt controls, and the injected-truth manifest. |
| `qualify_temporal.py` | Compares a checker's answers to the injected truth and writes the qualification record it earned — which, deliberately, can never be `qualified`. |
| `validate_package.py` | Checks our own claims: no network, no provider SDK, no invented pass mark. |
| `perturbation-contract.yaml` | Machine-readable: each perturbation, the frozen capability it serves, and what it cannot establish. |
| `PERTURBATION-SPEC.md` | The protocol in full, including the honest limits. |
| `tests/` | 153 tests. |

## ⚠️ Two warnings that must not be lost

**1. Nothing here qualifies anything.** Zero instruments are qualified in this project and this
package does not change that. It builds the material and the arithmetic a qualification run would
need. The run itself has not happened, because the clean base clips do not exist yet.

**2. The stand-in clips are not the pack.** `build_dummy_clips.py` draws coloured shapes on flat
backgrounds. They exist to prove the code runs end to end. A checker that finds a moving colour
block has been told nothing about whether it can spot identity drift in a real face. Every
artifact built from them is stamped `material_class: constructed_stand_in`, the manifest sets
`is_approved_qualification_pack: false`, and the scoring harness returns **`unmeasurable`** on
them no matter how good the answers are. That is a code-level lock, not a note in a document.

## What it produces

Run against the twelve stand-in clips:

```
base clips              12
perturbed fixtures      146
clean controls          12
corrupt controls        7 (all refused, as required)
perturbation types      13
material classes        constructed_stand_in
approved qualification pack: False
external calls 0 · human labels 0 · spend USD 0.0
```

Every fixture carries, in `MANIFEST.json`:

- the **source clip hash** (and, for real footage, the delivered file's own hash as well);
- the **transformation and every parameter** it was given;
- the **affected frame interval and time interval**;
- the **affected region**, where the defect is spatial, and whether that region was declared or
  defaulted from geometry;
- the **output hash**, so any rebuild can be proved identical;
- the **motion load** of both source and output — a recorded condition the frozen capability
  contract requires, because a near-static clip scores perfectly on smoothness and would flatter
  a motion checker that cannot actually judge motion;
- the **independent-opportunity id**, which is the base clip. Thirteen fixtures cut from one clip
  are one opportunity, never thirteen.

## How to run it

Build and verify the stand-in pack (about a minute, all local):

```bash
python3 eval/v1/instruments/temporal-perturbation/build_perturbation_pack.py --build --rebuild-check
```

```bash
python3 eval/v1/instruments/temporal-perturbation/build_perturbation_pack.py --verify
```

Exercise the scoring arithmetic without any checker at all — this fabricates answers with a known
flaw and shows the report catching it:

```bash
python3 eval/v1/instruments/temporal-perturbation/qualify_temporal.py --manifest eval/v1/instruments/temporal-perturbation/fixtures/pack/MANIFEST.json --selftest-profile blind_to_text
```

Check the zero-spend claim:

```bash
python3 eval/v1/instruments/temporal-perturbation/validate_package.py
```

Tests (pytest in a throwaway virtualenv outside the repository, as this project already does):

```bash
python3 -m pytest -q eval/v1/instruments/temporal-perturbation/tests
```

When the approved clips arrive, the only new step is one config file naming them:

```bash
python3 eval/v1/instruments/temporal-perturbation/build_perturbation_pack.py --build --ingest-config <path>/clips.json
```

The fixture plan is written in fractions of clip length, not fixed frame numbers, so the identical
plan applies to a 48-frame stand-in and to a 480-frame real clip with no editing.

## Why the built frames are not committed

The pack writes several thousand PNG frames. They are git-ignored and the manifest's hashes are
committed instead.

This is **not** the same rebuild risk as the Devanagari battery. That battery depends on an
uncommitted proprietary font, so a fresh clone genuinely cannot reproduce it. These clips are
generated by committed code using only the Python standard library, with integer arithmetic and no
randomness that is not seeded from the content itself. A fresh clone rebuilds them exactly, and
`--rebuild-check` proves it by rebuilding into a scratch directory and comparing hashes.

## What is deliberately missing

**Audio/video synchronisation.** The family-4 spec lists "shift audio by a known number of
milliseconds" alongside the visual perturbations. It is not implemented here for two reasons: the
frozen qualification map files that capability under evaluator family 5 (speech/audio/AV), not
temporal video; and the project holds no audio of any kind, so the machinery would have nothing to
run on. The construction is straightforward and should be added when AV material exists. Recorded
in `perturbation-contract.yaml` under `out_of_scope`.

**A pass mark.** No number anywhere in the frozen contracts says what recall or what false-alarm
rate is good enough for this family. None is invented here. The scoring harness computes the three
measures the frozen gate asks for and returns `gate_verdict: undetermined` until the Controller
sets one. `validate_package.py` fails if a threshold constant ever appears in the code.
