# GOV-001 — Initial Repository Hygiene + Authoritative State Reconstruction

**Status:** OPEN — Controller-assigned after governance design approval
**Role:** Repository Governor (fifth independent agent)
**Scope:** governance/control plane only
**Execution branch:** `work/gov-001-initial-repository-hygiene`

## Read first

1. `docs/superpowers/specs/2026-08-25-repository-governor-project-memory-design.md`
2. `docs/superpowers/plans/2026-08-25-governor-reset-cleanup-plan.md`
3. `coordination/PROJECT-CONTRACT.md`
4. `shared/COMMUNICATION-STANDARD.md`

Then inspect the whole current repository from GitHub. Do not rely on chat history.

## Objective

Perform the project's first Governor reset audit. Reconstruct authoritative project state from committed GitHub evidence, establish the canonical `PROJECT-MEMORY.md`, create the durable Governor contract, and clean/mark the operational documentation layer so a zero-context agent months later cannot reasonably mistake stale history for current truth.

This first pass is intentionally more exhaustive than future routine Governor reviews.

## Hard boundaries

- GitHub is the source of truth. Chat is not evidence.
- Audit the exact current `main` SHA and record it.
- Canon, Eval, and Resources domain artifacts are read-only evidence for GOV-001 unless the approved governance write boundary explicitly permits a status/supersession marker in an operational document.
- Do **not** alter Canon source knowledge, audit records, Eval batteries/results/thresholds, Resources datasets/manifests, schemas, product architecture, benchmark methodology, or historical baselines.
- Do **not** start or authorize CANON-009, EVAL-006, Resources expansion, acquisition work, Capability Registry work, Production IR work, or any other new domain task.
- Do not perform large file moves/deletions merely to make the repo look tidy.
- If a domain-owned inconsistency is real, route it with evidence rather than silently fixing it.
- Do not promote recommendations or chat recollections into decisions.

## Required deliverables

1. `PROJECT-MEMORY.md`
   - curated rolling synthesis;
   - understandable with zero chat history;
   - current thesis, architecture, boundaries, frozen decisions, stream states, established lessons/results, limitations/unresolved issues, current freeze/next gates, milestones, authority map, and material verification qualifiers;
   - concise enough to be the standard bootstrap document.

2. `governance/GOVERNOR-CONTRACT.md`
   - fifth-agent role;
   - per-task review protocol;
   - periodic audit cadence;
   - PASS / PASS WITH NON-BLOCKING NOTES / BLOCK verdicts;
   - write boundaries and escalation/routing rules;
   - explicit prohibition on methodology redesign during integrity review.

3. `governance/audits/2026-08-25-initial-repository-hygiene-audit.md`
   - audited `main` SHA;
   - exhaustive inventory/classification of operational/state documents;
   - every material contradiction/staleness issue found;
   - severity and evidence;
   - resolution status: corrected / historical-or-superseded / routed / unresolved;
   - verification performed and limitations.

4. Targeted corrections/status markers to central operational documentation where required so stale material cannot masquerade as current state.

## Exhaustive audit requirement

Inspect all files or sections that function as any of the following:

- current/control state;
- workstream status;
- handoff/session bootstrap;
- task queue/status;
- decision register/log;
- runbook;
- roadmap;
- charter/contract with current operational implications;
- resource request/current dependency;
- audit/current-state summary;
- acquisition/current research state referenced from GitHub.

Search semantically as well as by filename. A document containing current-state claims is in scope even if its filename does not say `STATE` or `STATUS`.

Classify each operational/state document using exactly one primary class:

- `CURRENT_AUTHORITY`
- `SUPPORTING_CURRENT`
- `HISTORICAL`
- `SUPERSEDED`
- `REQUIRES_CORRECTION`

## Known audit leads — verify, do not assume

Controller's preliminary read-only audit found possible drift in areas including `coordination/CONTROL-STATE.md`, `coordination/WORKSTREAM-STATUS.md`, `coordination/DECISION-LOG.md`, `coordination/RUNBOOK.md`, `coordination/AUTOMATION-ROADMAP.md`, and accumulated stream handoffs. Treat these only as leads. Independently verify every finding against current GitHub evidence and look for additional issues.

Also verify that the latest merged Canon and Eval outcomes are represented consistently, including the distinction between historical and live Canon counts and the post-human-validation EVAL-005 state. Do not take any chat-supplied number as truth; derive/check it from the repo.

## Verification

Before opening the PR:

- run existing relevant validators/tests available in the repository;
- record exact commands and outputs/failures;
- search for stale current-state phrases/numbers found during the audit and distinguish legitimate historical uses from misleading live uses;
- inspect links/paths added by GOV-001;
- compare final diff with the audited baseline and prove the task did not alter domain evidence/methodology outside its write boundary;
- perform the zero-chat bootstrap test using only `PROJECT-MEMORY.md` and linked GitHub files.

If an environment limitation prevents verification, state that explicitly. Never convert an unrun check into a pass.

## Return / stop condition

Open one PR to `main` from `work/gov-001-initial-repository-hygiene` and stop.

Return to Controller with:

- PR number + head SHA;
- audited baseline SHA;
- concise reconstructed current state;
- high-severity contradictions fixed;
- issues routed/unresolved;
- operational-document classification summary;
- exact verification evidence and environment limitations;
- final Governor verdict.

Do not merge. Do not begin GOV-002. Do not begin any domain task.
