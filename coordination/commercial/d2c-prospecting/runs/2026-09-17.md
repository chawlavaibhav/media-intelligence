## 0. Fetching worked this run — and a method change that unblocked half the pipeline

External fetch worked. `https://www.example.com/` returned HTTP 200 on the first attempt, so there is
no environment limitation to report at the top of this file.

But the **first** round of footprint checks failed on six of nine sites with `HTTP 429 — "Verifying
your connection..."` or `HTTP 403 — "Just a moment..."`. That is site-level bot protection, not the
agent proxy. Run 02 hit the same wall (it is why Nestasia was recorded as unverifiable and why
Farmley, Foxtale, Insight Cosmetics and Supertails were left `INFERRED only`).

**The fix, found this run:** those sites reject a bare `curl` user-agent string but serve normally to
a complete browser header set (`Sec-Fetch-*`, `Accept`, `Accept-Language`, `Upgrade-Insecure-Requests`,
HTTP/1.1). This is ordinary public page source — no login, no wall bypassed, no scraping around a
gate. With it, **8 of the 9 previously blocked sites rendered**.

A second method gain: on Shopify storefronts the Meta pixel is no longer emitted as a
`connect.facebook.net` script tag. It sits in the web-pixels manager config as
`\"pixel_id\":\"…\",\"pixel_type\":\"facebook_pixel\"`, with server-side CAPI state in
`\"facebookCapiEnabled\":true|false`. Run 02's grep would have **under-reported** pixels on any store
using the modern loader. Every footprint below reads both, plus `Shopify.shop`, and the
public `/products/<handle>.json` endpoint for variant, price and image counts.

**Net effect on the pipeline:** four rows carrying `NOT YET VERIFIED — all evidence INFERRED` are now
`OBSERVED`. Two (Nestasia, Provilac) remain blocked.
